# [상세 설계 문서] 증거 우선주의 기반 법과학 분석 아키텍처
## (Evidence-First Forensic Analysis Architecture)

### 1. 설계 철학 (Core Philosophy)
**"전문가는 객관적으로 조사하고, 판단은 아비터(Arbiter)가 통합적으로 내린다."**

본 설계는 개별 전문가 모델의 확증 편향(Confirmation Bias)을 억제하고, 화재 현장의 모든 파편적인 증거를 하나의 '판단 엔진(Arbiter)'으로 결집시키는 **중앙 집중형 판정 구조**를 지향합니다.

---

### 2. 역할의 재정의 (Role Redefinition)

| 계층 | 역할명 | 주요 임무 (Responsibility) |
| :--- | :--- | :--- |
| **Stage 1 (Worker)** | **현장 조사관 (Investigator)** | 핫스팟의 기하학적 형태, 변색, 질감을 **시각적 사실(Visual Fact)** 위주로 정밀 기술 |
| **Stage 2 (Expert)** | **기술 자문관 (Consultant)** | 조사된 사실들이 자신의 도메인(예: 접촉불량)에서 갖는 **전문적 의미(Context)**를 예비 소견으로 제출 |
| **Stage 3 (Arbiter)** | **최종 판관 (Judge)** | 모든 전문가의 증거 리스트와 소견을 종합하여 **화재의 근본 원인(Final Verdict)**을 확정 |

---

### 3. 세부 워크플로우 (Detailed Workflow)

#### **Phase 1: 증거 기반 조사 (Evidence Gathering)**
*   전문가 노드는 "이것은 [원인]이다"라는 결론을 내리지 않습니다.
*   대신, 해당 분야에서 중요하게 다루는 **체크리스트**를 바탕으로 증거를 나열합니다.
    *   *예 (Contact Expert):* "비드의 표면 광택 유무", "주변 탄화물의 결정 구조", "아산화동 형성 여부" 등을 객관적으로 기록.

#### **Phase 2: 전문가 예비 소견 (Preliminary Opinion)**
*   전문가 서브그래프의 `Supervisor`는 취합된 증거들을 검토하여 짧은 소견을 덧붙입니다.
    *   *소견 예시:* "발견된 3개의 비드 중 2개가 매끄러운 표면을 가짐. 이는 접촉불량 초기 단계에서 나타나는 전형적인 패턴과 80% 가량 일치함."

#### **Phase 3: 아비터 통합 판정 (Centralized Verdict)**
*   아비터는 각 과별 '진단서'가 아닌, **'검사 결과지' 전체**를 테이블에 올립니다.
*   **교차 검증:** "A 전문가가 찾은 비드 흔적"과 "B 전문가가 발견한 외력 흔적"이 서로 모순되는지 혹은 상호 보완되는지 판단하여 최종 인과관계를 확정합니다.

---

### 4. 데이터 스키마의 변화 (Data Schema Evolution)

전문가가 아비터에게 전달하는 데이터 구조는 **결론 중심에서 증거 중심으로** 변경됩니다.

```json
{
  "expert_id": "Contact_Expert",
  "evidence_list": [
    {
      "hotspot_id": 1,
      "visual_evidence": "직경 2.5mm의 매끄러운 구형 비드, 주변에 붉은색 산화물 부착",
      "certainty_of_fact": 95 // "사실" 자체에 대한 확신도
    }
  ],
  "preliminary_opinion": "해당 증거들은 전기적 원인에 의한 용융 가능성을 강하게 시사함.",
  "domain_confidence": 85 // 자기 도메인 관점에서의 의심 수준
}
```

---

### 5. 아키텍처 도입의 기대 효과 (System Benefits)

1.  **논리적 투명성:** 최종 판결의 근거가 전문가의 추측이 아닌, **나열된 시각적 증거들**로부터 직접 연결됩니다.
2.  **도메인 간 시너지:** 아비터가 모든 팩트를 한곳에 모아 보게 되므로, 전문가 개인이 놓친 **'현장 전체의 스토리'**를 발견할 수 있습니다.
3.  **검증 가능성:** 나중에 분석 결과를 사람이 검토할 때, AI가 어떤 팩트를 보고 그런 결론을 내렸는지 명확히 추적(Traceability)할 수 있습니다.

---

본 아키텍처는 화재 조사 AI가 단순한 분류기를 넘어, **"논리적인 화재 감식관"**으로 진화하기 위한 가장 중요한 발판이 될 것입니다.
