# Upscale 2배 → 4배 변경 영향 분석

## 현재 상황

- **SR_SCALE**: 2 (2배 upscale)
- **모델**: Real-ESRGAN x4plus (원래 4배 upscale 지원)
- **ONNX 모델**: x4 모델 (4배 upscale 후 resize로 2배로 축소)
- **백엔드**: DirectML (AMD GPU 가속)

## 변경 시 영향 분석

### 1. 이미지 크기 변화

| 항목 | 2배 (현재) | 4배 (변경 후) | 변화율 |
|------|-----------|--------------|--------|
| **픽셀 수** | 4배 증가 | 16배 증가 | **4배 증가** |
| **예시 (100x100)** | 200x200 (40K 픽셀) | 400x400 (160K 픽셀) | 4배 |
| **예시 (500x500)** | 1000x1000 (1M 픽셀) | 2000x2000 (4M 픽셀) | 4배 |

**결론**: 이미지 크기가 4배 증가하여 메모리 사용량도 4배 증가합니다.

### 2. 처리 시간 영향

#### 현재 동작 방식 (SR_SCALE=2)
```
입력 이미지 → ONNX 모델 (4배 upscale) → Resize (2배로 축소) → 최종 출력
예: 100x100 → 400x400 → 200x200
```

#### 변경 후 (SR_SCALE=4)
```
입력 이미지 → ONNX 모델 (4배 upscale) → 최종 출력 (resize 제거)
예: 100x100 → 400x400
```

**예상 처리 시간**:
- **DirectML 추론 시간**: 거의 동일 (모델은 동일하게 4배 upscale 수행)
- **Resize 단계 제거**: 약 5-10ms 절약
- **전체 처리 시간**: 약 5-10% 감소 가능 (resize 제거 효과)

**현재 성능 (로그 기준)**:
- DirectML 추론: 약 0.15-0.88초 (이미지 크기에 따라 다름)
- 4배로 변경 시: 추론 시간은 동일, resize 제거로 약간 개선

### 3. 메모리 사용량

| 항목 | 2배 (현재) | 4배 (변경 후) | 변화율 |
|------|-----------|--------------|--------|
| **중간 버퍼 (ONNX 출력)** | 400x400x3 (약 1.9MB) | 400x400x3 (약 1.9MB) | 동일 |
| **최종 이미지** | 200x200x3 (약 480KB) | 400x400x3 (약 1.9MB) | **4배 증가** |
| **전체 메모리** | 약 2.4MB | 약 3.8MB | **약 1.6배 증가** |

**결론**: 메모리 사용량이 증가하지만, 현대 시스템에서는 문제가 되지 않을 수준입니다.

### 4. Gemini API 비용 영향

#### 이미지 토큰 계산 (Gemini API)
- Gemini API는 이미지 크기에 따라 토큰 수가 결정됩니다.
- **MEDIA_RESOLUTION_HIGH** 사용 시:
  - 이미지 크기가 클수록 더 많은 토큰 사용
  - 대략적으로 픽셀 수에 비례

#### 예상 비용 증가
| 이미지 크기 | 2배 (현재) | 4배 (변경 후) | 토큰 증가율 |
|------------|-----------|--------------|------------|
| **100x100 →** | 200x200 | 400x400 | 약 4배 |
| **500x500 →** | 1000x1000 | 2000x2000 | 약 4배 |

**Gemini API 토큰 비용**:
- 현재 (2배): 약 1,120 tokens/이미지 (HIGH 해상도 기준)
- 변경 후 (4배): 약 2,240 tokens/이미지 (ULTRA_HIGH 해상도 수준)
- **비용 증가**: 약 2배

**참고**: `config.py`의 주석에 따르면 ULTRA_HIGH는 비용이 2배 증가합니다.

### 5. 분석 품질 향상

#### 장점
1. **세부 정보 향상**: 4배 해상도로 미세한 특징을 더 잘 식별 가능
2. **화재 조사 정확도**: 작은 단락흔, 미세한 변형 등을 더 정확히 분석
3. **LLM 분석 품질**: 더 높은 해상도로 인한 더 정확한 시각적 분석

#### 실제 효과
- **2배 (현재)**: 기본적인 단락흔 특징 식별 가능
- **4배 (변경 후)**: 미세한 표면 변화, 작은 크랙, 미세한 변색 등 더 정확히 식별

**결론**: 화재 조사와 같은 세밀한 분석이 필요한 경우, 4배 upscale이 분석 품질을 크게 향상시킬 수 있습니다.

## 종합 평가

### 장점 ✅
1. **분석 품질 향상**: 세부 정보 식별 능력 크게 향상
2. **코드 효율성**: 불필요한 resize 제거로 약간의 성능 향상
3. **모델 활용**: x4plus 모델의 원래 성능을 최대한 활용

### 단점 ⚠️
1. **메모리 사용량 증가**: 약 1.6배 증가 (하지만 현대 시스템에서는 문제 없음)
2. **API 비용 증가**: Gemini API 토큰 비용 약 2배 증가
3. **처리 시간**: DirectML 추론 시간은 동일하지만, 전체 파이프라인에서 이미지 전송 시간 증가 가능

### 권장 사항

#### ✅ 4배로 변경 권장하는 경우
- **세밀한 분석이 중요한 경우**: 화재 조사, 법의학적 분석 등
- **비용이 큰 문제가 아닌 경우**: API 비용 증가를 감수할 수 있는 경우
- **메모리가 충분한 경우**: 시스템 메모리가 충분한 경우

#### ⚠️ 2배 유지 권장하는 경우
- **비용 최적화가 중요한 경우**: API 비용을 최소화해야 하는 경우
- **빠른 처리 속도가 중요한 경우**: 실시간 분석이 필요한 경우
- **메모리가 제한적인 경우**: 임베디드 시스템이나 제한된 리소스 환경

## 결론

**4배로 변경 시 분석 차이는 상당히 클 것으로 예상됩니다.**

특히 화재 조사와 같은 세밀한 분석이 필요한 경우, 4배 upscale은 다음과 같은 이점을 제공합니다:

1. **분석 품질**: 미세한 특징 식별 능력 크게 향상
2. **코드 효율성**: 불필요한 resize 제거
3. **모델 활용**: x4plus 모델의 원래 성능 활용

단, API 비용이 2배 증가하므로, 비용과 품질의 트레이드오프를 고려하여 결정하는 것이 좋습니다.
